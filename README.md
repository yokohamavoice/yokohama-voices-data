# ヨコハマの声　公開データ

このリポジトリには、確認・承認を終えた公開データだけを保存します。最初の公開版が作られるまでは説明と分析用スクリプトのみです。

ヨコハマの声の運営者（すすすす）が内容を確認し、承認したデータを公開します。ログインなしでダウンロードし、分析できます。

## データを取得する

- `data/manifest.json`：最新の承認済み版への参照。**Code → Download ZIP** で取得できます。
- `releases/<公開版ID>/dataset.json`：版ごとに固定したルート。schema 3では同じフォルダの `parts/` も一緒に取得します。
- サイトの `/api/export`：最新の承認済みの版。サイトのURLは専用の公開先が決まってから案内します。
- サイトの `/technology` に技術解説、`/research` に研究利用とデータ公開の説明があります。

公開前の投稿や未確認の原データを自動保存する方式は終了しました。運営者が候補データを確認し、その版を公開した後に、原則毎時17分の保存処理が取り込みます。公開候補の作成後に増えた回答は、その版には入りません。

| ファイル | 内容 |
| --- | --- |
| `releases/<ID>/parts/d-opinions-*.jsonl` | 本文、分野、初期意見／参加者投稿、資料ID、投稿日 |
| `releases/<ID>/parts/d-responses-*.jsonl` | セッションID、投稿ID、回答種別、分析用の値 |
| `releases/<ID>/parts/d-presentations-*.jsonl` | 提示ID、セッションID、投稿ID、提示順、抽選確率、配信方式の版、表示通知・回答・取消の有無 |
| `data/tags.json` / `sources.json` | 政策分野と参考資料 |
| `data/manifest.json` | 公開版ID、対象時点、件数、JSON全体のSHA-256 |

schema 3は分割JSONLと、各ページのハッシュを含む分割インデックスです。すべてを取得・検証してから最新版への参照を更新します。旧schema 2の `data/*.jsonl` と過去版も分析スクリプトで読めます。

## 読み方

`session_id` は一度の参加を表す無作為なIDです。同じ人の再参加は別IDです。参加セッション数は実人数や横浜市民全体の人数ではありません。投稿者と回答セッションの対応、認証情報、回答や表示の詳しい時刻、通報者の情報は公開用データに含めません。自由記述や回答の組合せから個人が推測される可能性は残ります。

| `response` | 意味 | `analysis_value` |
| --- | --- | --- |
| agree | 賛成 | -1 |
| disagree | 反対 | 1 |
| pass | パス | 0 |
| unrelated | 横浜市の政策に無関係 | null |

「無関係」は運営者が確認するための回答で、自動削除の判定ではありません。パスと未回答は別です。初期意見は `kind=seed` で、市の資料を参考に作成したものです。候補者の発言や市民の実投稿の引用ではありません。

提示記録の `displayed` はブラウザから表示通知を受信したことを表し、読まれた証明ではありません。`answered` は回答の有無、`retired` は運営上の非表示などで提示を取り消したかを表します。ページを開いたまま離れたこと、通信が切れたことを完全に区別することはできません。

`probability` はその提示時点の候補と履歴に基づく条件付き抽選確率です。市民全体の代表性を補う重みや、その人が研究に参加する確率ではありません。候補全体の履歴・詳細な時刻・結果閲覧などの原記録は管理者の保管場所に残ります。

公開データは掲載承認済みの投稿を対象にするため、除外された投稿の提示順が抜ける場合があります。以前の保存分に提示記録がない場合、後から復元したものは足しません。過去に公開した版は、投稿を非表示にしても自動的には書き換わりません。

## 分析例

Python 3で `python3 analysis/make_matrix.py` を実行すると、`analysis/output/vote_matrix.csv` に回答表を作れます。行はセッション、列は意見、パスは0、未回答と無関係は空欄です。両者を区別する集計には元の回答データを使ってください。

分析結果を公表するときは、サイト名、公開版ID、対象時点、利用した計算方法を明記してください。公開版の照合には、その版の `dataset.json` に対するSHA-256を使います。候補選びに使ったデータと、候補の支持を検証するデータを分けて考える必要があります。

## 更新と問い合わせ

このリポジトリの **Actions → Save public dialogue data** で保存処理の実行状況を確認できます。GitHub側で実行が遅れることがあります。公開リポジトリで60日間活動がないと定期実行が無効になる場合があります。新しい公開版がないときは保存内容を変えません。取得・照合に失敗した場合は前のデータを保持します。

公開候補は500原行ずつ作成し、途中から再開できます。従来の総件数による一括上限はありません。GitHubでも小さなファイルのまま保持します。容量や実行時間など、利用基盤の上限は別にあります。

問い合わせ先はサイトの `/research` で案内します。専用の連絡先は susususu.yoko@gmail.com です。GitHubのIssuesを利用する場合、内容は公開されます。個人情報や削除対象の文章を転載せず、投稿IDと相談の種類だけを書いてください。過去の公開版や第三者のコピーまで完全に削除できるとは限りません。投稿文の権利を一括して放棄させるものではありません。

## 専用アカウントでの設定

ワークフローは初期状態で停止します。Settings → Secrets and variables → Actions のVariablesへ次を設定します。接続先を入れるだけでは実行されません。公開・再開の指示後にだけ有効化してください。

| 変数 | 値 |
| --- | --- |
| `SITE_ORIGIN` | 専用サイトのHTTPSのオリジン（パスなし） |
| `PUBLIC_DATA_REPOSITORY` | この専用リポジトリの `owner/repository` |
| `PROJECT_OPERATOR_LOGIN` | 専用の実行者アカウント名 |
| `PUBLIC_SYNC_ENABLED` | 準備中は `false`。明示的な再開時だけ `true` |

実行元のリポジトリ・mainブランチ・実行者が一致しない場合は接続しません。自動保存のコミット名はGitHub Actionsのbotです。新しいリポジトリには過去のgit履歴や以前の公開データをそのまま移さず、確認済みのファイルから新しく作ります。履歴を作る前に、コミット名「すすすす」と専用メール（または専用アカウントの非公開用メール）を設定してください。
